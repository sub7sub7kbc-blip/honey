# GoldenHive — Honey E-Commerce (deployable version)

100% pure honey shop: Sidr, Acacia, Multiflora, Sarson (250g / 500g / 1kg) + Raw
Honeycomb 400g. Light honey-cream theme, animated Pure Honey slider, Order Builder,
Custom Order, cart + checkout (COD / EasyPaisa / JazzCash / Bank Transfer), WhatsApp
order send, Track Order by phone or order ID, customer login/signup, PIN-locked
Admin Panel (Dashboard, Orders, Products, Customers, Homepage & Slider,
Settings & Security). **Real system: prices and payment numbers are empty until
the owner sets them in Admin — no demo data, no demo orders.**

## How it is live — 100% FREE

```
Code → push to GitHub (private repo) → Render auto-deploys (~5 min) → site live
Database → Neon PostgreSQL (free) → connection string lives ONLY in Render env vars
```

GitHub does NOT host the site directly — GitHub holds the code, Render runs it,
Neon holds the data.

## Project layout

## Step-by-step deploy

1. **Local check** (optional but recommended):
   ```bash
   cd web && npm install && npm run build   # must succeed
   cd ../api && npm install && npm run test:smoke   # boots API on pg-mem, full flow
   ```
   To run the API for real locally you need Postgres (e.g. `apt install postgresql`
   or a Neon project) and a `.env` in `api/` with `DATABASE_URL` + `JWT_SECRET`,
   then `cd api && npm start`.
2. **Create a NEW private GitHub repo** and push this folder (include `render.yaml`).
   ```bash
   git init && git add . && git commit -m "GoldenHive live v1"
   git remote add origin https://github.com/<you>/goldenhive.git
   git push -u origin main
   ```
3. **Create a NEW Neon project** (region Singapore), database `neondb`. Copy its
   connection string from the Neon dashboard.
4. **On Render: New → Blueprint** → connect the new repo. It creates both services
   from `render.yaml` (`goldenhive-web` static site + `goldenhive-api` web service).
5. **Set the API env vars** in Render → `goldenhive-api` → Environment:
   - `DATABASE_URL` — the Neon connection string (never in code/GitHub).
   - `JWT_SECRET` — auto-generated by the Blueprint (`generateValue: true`); keep it secret.
   - `PORT` — Render sets this automatically; the app listens on it.
6. **Fix the frontend API URL:** after the first deploy, set `VITE_API_URL` on the
   `goldenhive-web` service to `https://goldenhive-api.onrender.com` (your real API
   URL), then redeploy the web service once. The frontend is built knowing the
   API's public URL.
7. **Verify:** open the site, then `GET https://<your-api>.onrender.com/api/v1/health`
   must return `{"status":"ok","db":"up"}`. Migrations + seed run on API boot.
8. **First setup in the live Admin Panel:** open the site → Admin → set your admin
   PIN (first use, 4–8 digits — never use a test PIN on the live site), then set
   real product prices, WhatsApp number, EasyPaisa/JazzCash numbers + titles and
   bank details. Until prices are set, products show "Price coming soon".
9. **Test like a customer** on the LIVE urls, not just localhost: sign up, order
   (COD), admin login, mark payment Paid, track the order.

## Free-tier traps (we hit all of these on the demo shop)

1. **API sleeps after 15 minutes idle** → the next visitor waits 30–60 s.
   Fix: a keep-alive ping to `/api/v1/health` every 10 minutes during active
   hours only (06:00–24:00 PKT). The health endpoint touches the database, so
   one ping wakes the API **and** Neon. (Use UptimeRobot free, or a cron job.)
2. **750 free instance-hours/month per Render service.** Keeping the API awake
   24×7 ≈ 720 h — too close to the limit. Waking hours only (18 h/day ≈ 540 h)
   stays safely inside.
3. **Neon free compute also sleeps** — covered by the same health ping.
4. **Files on the free disk are wiped on every redeploy.** Uploaded product
   photos are stored INSIDE the database (`product_photos` bytea column) — never
   the local disk.
5. First load right after a deploy is still slow once; after that it is fast.

## Auto-deploy

Render is connected to the GitHub repo. Every `git push` to `main` auto-deploys
both services in about 5 minutes. No manual steps.

## Cost

Rs. 0 — GitHub free + Render free + Neon free. A custom domain is the only thing
that costs money later (optional).

## Security notes

- Admin PIN is stored only as a salted scrypt hash; login exchanges it for a
  12-hour session token (only its hash is stored). 5 wrong PIN tries lock login
  for 5 minutes. Every owner action requires a valid admin token, server-side.
- Customer passwords are bcrypt-hashed, never plain text. Customer sessions are
  JWTs signed with `JWT_SECRET`.
- No real passwords, API keys or payment numbers are in this repo. The test PIN
  `2468` and test number `03001234567` appear only in `api/test-smoke.cjs`
  (test-only, in-memory DB) — never use them on the live site.
